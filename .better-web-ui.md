# Design Context

## Users

Visitantes técnicos y estudiantes que abren una web concreta del catálogo para resolver una tarea puntual (probar una regex, formatear datos, comparar texto). Llegan desde el catálogo, no desde buscadores, y esperan una herramienta que funcione sin cuenta ni servidor.

## Brand Personality

Útil, precisa y con criterio. Cada web puede tener carácter propio, pero ninguna debe sentirse como una plantilla genérica de SaaS.

## Aesthetic Direction

Una identidad por web, no una plantilla por web. Las webs comparten accesibilidad, tokens semánticos, footer y convenciones de código, pero **no** comparten shell, retícula, tipografía, paleta ni forma. Direcciones ya asignadas:

- `web-regex-tester`: **Workbench**. Consola oscura, mono, barra de comando, split entrada/salida, esquinas mínimas, acento lima.
- `web-json-yaml`: **Gutter**. Papel cálido, serif editorial, dos hojas enfrentadas, reglas dobles, anotaciones al margen, acento óxido.
- Próximas herramientas: elegir una dirección no usada (por ejemplo Ribbon, Blueprint o Pulse) antes de escribir CSS.

Antipatrones prohibidos: reutilizar el mismo hero centrado, los mismos paneles redondeados, la misma pareja tipográfica o el mismo ritmo vertical entre dos webs distintas. Cambiar solo la paleta no cuenta como dirección nueva.

## Implementation Defaults

- HTML5 semántico, CSS con custom properties y capas, JavaScript como módulos ES nativos; sin frameworks ni build por web.
- Librerías de terceros vendorizadas dentro de cada web, nunca por CDN.
- Tipografías vía Google Fonts; datos y código en mono, texto de interfaz en la familia elegida por la dirección.
- Tests de lógica pura en `tests/<web>/`, captura en `assets/screenshots/<web>.webp` y entrada en `projects.yml`.

## Design Principles

1. Elegir primero la topología (una columna, split, hojas, flujo único) y después el estilo; nunca al revés.
2. La tipografía y la densidad definen la identidad más que el color.
3. Una sola acción primaria visible por bloque; el resto, acciones discretas.
4. Español en la interfaz y en la documentación; inglés en identificadores, módulos y comentarios.
5. Toda web debe verse como una herramienta distinta, no como una sección de la anterior.
6. El footer es común: «Todos los derechos reservados - año dinámico jeironpro».
