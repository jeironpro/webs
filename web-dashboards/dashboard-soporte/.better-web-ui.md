# Contexto de proyecto

## Design Context

### Users

- **Usuarios principales**: agentes de un equipo de soporte que consultan y gestionan tickets (ver estado, prioridad, canal y conversaciones) y supervisores que revisan métricas de respuesta y resolución.
- **Audiencia secundaria**: reclutadores y desarrolladores que revisan este repositorio como portafolio; el código debe demostrar buenas prácticas.
- **Job to be done**: entender de un vistazo el estado del soporte (abiertos, en progreso, cerrados), el tiempo de respuesta promedio y el historial de cada conversación.

### Brand Personality

- Tres palabras: **claro, confiable, eficiente**.
- Tono neutral y cálido; lenguaje en **español**.
- Debe transmitir serenidad operativa, no urgencia ni ruido.

### Aesthetic Direction

- **Light, minimalista y editorial**: neutros cálidos (creto con tintes arena), un único acento verde pino; tipografía display serif (Fraunces) para encabezados y sans (Geist Variable) para datos y UI; esquinas ligeramente suaves; mucho espacio en blanco y ritmo de espaciado variable.
- Anti-referencias: dashboards oscuros con neón, glassmorphism genérico, tarjetas idénticas en rejilla, hero de métricas "big number + gradient".
- La jerarquía debe sostenerse en escala de grises: peso, tamaño, espaciado y contraste primero; color solo como refuerzo semántico.

### Implementation Defaults

- **Stack**: React 19 + Vite + TypeScript, empaquetado con **Yarn 4** (`nodeLinker: node-modules`), Tailwind CSS v4, shadcn/ui (flavor **Base UI**, preset base-nova), lucide-react.
- **Routing**: React Router (rutas `/`, `/tickets`, `/tickets/:id`).
- **Datagrid**: TanStack Table para el listado de tickets.
- **Gráficos**: Recharts con tabla de datos accesible como respaldo.
- **Forms/estado**: sin librería de formularios; estado local + UI optimista.
- **Tests**: Vitest + Testing Library + jest-dom; CI en GitHub Actions (lint, typecheck, test, build).
- **Datos**: mock JSON realistas en español bajo `src/data/`, con utilidades tipadas en `src/lib/`.
- Origen de estas decisiones: explicit user preference (setup, PR `chore/setup`) sobre defaults del framework.

### Design Principles

1. **Jerarquía con espaciado y peso antes que color**: la interfaz debe leerse correctamente en escala de grises; el verde pino es acento, no estructura.
2. **Un solo acento cromático por superficie**: neutros cálidos + un acento pino; los estados semánticos (estado/prioridad) usan su propio esquema mínimo y distinguible.
3. **Los datos primero, los gráficos después**: cada gráfico debe tener respaldo textual o de tabla accesible; nada decorativo sin significado.
4. **Acción clara por vista**: una acción primaria evidente y acciones secundarias discretas, sin competir por atención.
5. **Restricción y simetría en la interacción**: patrones reconocibles (tablas, filtros, timeline); el contenido es lo que destaca, no los efectos.
