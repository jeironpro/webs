Teoria: Base de Datos Relacionales

Base de datos relacionales
I. Concepto de base de datos

Una base de datos es una recopilación organizada de información o datos estructurados, que normalmente se almacena de forma electrónica en un sistema informático. Normalmente, una base está controlada por un sistema de gestión de bases de datos (dbms). Una base de datos se encarga no solo de almacenar datos, sino también de conectarlos entre sí en una unidad lógica. En conjunto, los datos y el dbms, junto con las aplicaciones asociadas a ellos, reciben el nombre de sistema de bases de datos, abreviado normalmente a simplemente base de datos.

II. Sentencias DDL SQL (CREATE - ALTER - DROP)

Sentencias DDL (Data Definition Language) son aquellas utilizadas para la creación de una base de datos y todos sus componentes: tablas, índices, relaciones, disparadores (triggers), procedimientos almacenados, etc. Estas sentencias se utilizan para crear, modificar y eliminar objetos de bases de datos como tablas, vistas, índices y procedimientos almacenados.

III. Sentencias DML (SELECT - INSERT - UPDATE - DELETE)

Sentencias DML (Data Manipulation Language) son aquellas utilizadas para recuperar, insertar, actualizar y eliminar los datos de una base de datos.

IV. Clausulas

Las cláusulas son condiciones de modificación utilizadas para definir los datos que desea seleccionar o manipular. Cláusulas más comunes: Select, From, Where, Order by, Group by, Having.

V. Operadores

Los operadores son símbolos que se utilizan para especificar una acción que se realiza en una o más expresiones. Categorías de operadores: aritméticos, relacionales, de asignación, de resolución de ámbito, bit a bit, de comparación, de concatenación de cadenas, compuestos, unarios y lógicos.

Operadores aritméticos:
ejecutan operaciones matemáticas con dos expresiones de uno o varios tipos de datos. Se ejecutan en la categoría de tipos de datos numéricos.
Operadores relacionales:
son elementos de la sintaxis que puede aceptar uno o varios parámetros de entrada con o sin nombre y devuelven un conjunto de resultados. Los operadores relacionales se usan como origen de tabla en instrucción DML.
Operador de asignación:
el signo igual (=) es el único operador de asignación de Transact-SQL. El operador de asignación también se puede utilizar para establecer la relación entre un encabezado de columna y la expresión que define los valores para esa columna.
Operador de resolución de ámbito:
proporciona acceso a los miembros estáticos de un tipo de datos compuesto. Un tipo de datos compuesto es aquel que contiene varios métodos y tipos de datos simples. En los tipos de datos compuestos, se incluyen los tipos de CLR integrados y los tipos definidos por el usuario de SQLCLR personalizados (UDT).
Operadores bit a bit:
realizan manipulaciones de bits entre dos expresiones de cualquiera de los tipos de datos de la categoría del tipo de datos entero. Los operadores de bit a bit convierten dos valores enteros en bits binarios y llevan a cabo la operación AND, OR o NOT correspondiente en cada bit, lo cual genera un resultado. Luego, convierten el resultado en un entero.
VI. Que significa CRUD?

CRUD (Create, Read, Update, Delete) es un acrónimo para las maneras en las que se puede operar sobre información almacenada. Es un nemónico para las cuatro funciones del almacenamiento persistente.

VII. Entidad

Una entidad es un objeto contenido en el modelo de datos. Cada entidad contiene miembros que son las filas de datos maestros que administra.

VIII. Atributos

Los atributos son objetos contenidos en Master Data Services entidades. Los valores de atributo describen los miembros de la entidad. Un atributo se puede usar para describir una miembro hoja, un miembro consolidado o una colección. Un valor de atributo es el valor que se usa para describir un miembro concreto. Cuando se crea una entidad que contiene muchos atributos, puede organizar los atributos en grupos de atributos. Además, al crear una entidad, se crean automáticamente los atributos Code y Name. Code requiere un valor y es preciso que sea único en la entidad. No puede quitar los atributos Code y Name.

IX. Relaciones

Las relaciones son asociaciones entre tablas que se crean utilizando sentencias de union para recuperar datos. Las relaciones se definen utilizando restricciones de clave principal a clave externa. Se crea un enlace entre dos tablas donde la clave principal de una tabla se asocia con la clave externa de otra tabla utilizando las relaciones de la base de datos.

X. Diagrama entidad-relacion

El diagrama entidad-relación (ERD) es un tipo de diagrama de flujo que ilustra cómo las entidades se relacionan entre sí dentro de un sistema.

XI. Cardinalidad

La cardinalidad es una restricción en una relación que especifica el número de instancias de entidad que una entidad específica puede estar relacionada a través de la relación. La cardinalidad es el número de entidades con la cual otra entidad se puede asociar mediante una relación binaria. La cardinalidad puede ser: uno a uno, uno a muchos o muchos a uno y muchos a muchos. El tipo de cardinalidad se representa mediante una etiqueta en el exterior de la relación, respectivamente: “1:1”, “1: N” y “N:M”, aunque la notación depende del lenguaje utilizado, la que más se usa actualmente es el unificado.

  • Gestión fácil de grandes conjuntos de datos.
  • Acceso sencillo y eficaz a los datos almacenados.
  • Gran flexibilidad.
  • Integridad y consistencia de los datos.
  • Control de acceso del usuario (seguridad y protección de datos).
  • Alta disponibilidad.
XVII. Tipos de datos

Un tipo de dato es un atributo que especifica el tipo de datos que el objeto puede contener: datos enteros, datos de caracteres, datos de moneda, datos de fecha y hora, cadenas binarias, etc.

  • Numéricos exactos: bigint, numeric, bit, smallint, decimal, smallmoney, int, tinyint y money.
  • Cadenas de caracteres Unicode: nchar, nvarchar y ntext.
  • Numéricos aproximados: float y real.
  • Cadenas binarias: binary, varbinary e image.
  • Fecha y hora: date, datetimeoffset, datetime2, smalldatetime, datetime y time.
  • Cadenas de caracteres: char, varchar y text.
  • Otros tipos de datos: cursor, rowversion, hierarchyid, sql_variant, xml, tipos de geometría espacial, tipos de geografía espacial y table.
XVIII. Modelo de datos

El modelo de datos es el proceso de creación de una representación visual o esquema que define los sistemas de recopilación y administración de información de cualquier organización. Este esquema o modelo de datos ayuda a las diferentes partes interesadas, como analistas de datos, científicos e ingenieros, a crear una vista unificada de los datos de una organización. El modelo esboza los datos que recoge de la empresa, la relación entre los distintos conjuntos de datos y los métodos que se usaran para almacenarlos y analizarlos. Un modelo de datos es una representación abstracta de datos almacenados en una base de datos relacional subyacente u otro origen de datos al que se pueda acceder.

XX. Modelo logico

Un modelo lógico es un modelo que no es específico de una base de datos que describe aspectos relacionados con las necesidades de una organización para recopilar datos y las relaciones entre estos aspectos. Un modelo lógico contiene representaciones de entidades y atributos, relaciones, identificadores exclusivos, subtipos y supertipos y restricciones entre relaciones. Un modelo lógico también puede contener objetos de modelo de dominio o referirse a uno o varios modelos de dominio o de glosario. Un modelo lógico describe los datos con el mayor detalle posible, independientemente de cómo se implementarán físicamente en la base de datos. Características del modelo lógico son:

  • Incluye todas las entidades y relaciones entre ellos.
  • Todos los atributos para cada entidad están especificados.
  • La clave principal para cada entidad esta especificada.
  • Se especifican las claves externas (claves que identifican la relación entre diferentes entidades).
  • La normalización ocurre en este nivel.
XXII. Normalizacion

La normalización es un proceso que consiste en designar y aplicar una serie de reglas a las relaciones obtenidas tras el paso del modelo entidad-relación al modelo relacional. Esto incluye la creación de tablas y el establecimiento de relaciones entre esas tablas de acuerdo con reglas diseñadas tanto para proteger los datos como para hacer que la base de datos sea más flexible al eliminar la redundancia y la dependencia inconsistente.

XXIII. Enlazar tablas

Enlazar tablas funciona haciendo coincidir datos en columnas de clave, normalmente columnas (o campos) que tienen el mismo nombre en ambas tablas. En la mayoría de los casos, la relación conecta la clave principal, o la columna de identificador único para cada fila, de una tabla a un campo de otra tabla. La columna en otra tabla se conoce como la clave externa. Hay tres tipos de relaciones entre tablas. El tipo de relación que se crea depende de cómo se definan las columnas relacionadas.

Relaciones de uno o varios:
es el tipo de relación más común. En este tipo de relación, una fila de la tabla A puede tener muchas filas coincidentes en la tabla B, pero una fila de la tabla B solo puede tener una fila coincidente en la tabla A.
Relación de varios a varios:
en una relación de varios a varios, una fula de la tabla A puede tener muchas filas coincidentes en la tabla B y viceversa. Esta relación se crea definiendo una tercera tabla denominada tabla de conexión. La clave principal de la tabla de conexión consta de las claves extranjeras de la tabla A y de la B.
Relación de uno a uno:
en una relación de uno a uno, una fula de la tabla A no puede tener más de una fila coincidente en la tabla B y viceversa. Se crea una relación uno a uno si ambas columnas relacionadas son claves principales o tienen restricciones únicas. Este tipo de relación no es común porque la mayoría de la información que está relacionada de esta manera estaría en una tabla. Se puede usar una relación uno a uno para las siguientes acciones:
  • Divide una tabla con muchas columnas.
  • Aislé parte de una tabla por motivos de seguridad.
  • Almacene datos de corta duración y que podría eliminarse fácilmente borrando la tabla.
  • Almacene información que solo se aplique a un subconjunto de la tabla principal.

Vistas

Vistas es un subconjunto de una base de datos y se basa en una consulta que se ejecuta en una o más tablas de base de datos. Las vistas de base de datos se guardan en la base de datos como consultas con nombre y se pueden utilizar para guardar consultas completas que se utilizar con frecuencia. Hay dos tipos de vistas de base de datos: vistas dinámicas y vistas estáticas. Las vistas dinámicas pueden contener datos de una o dos tablas e incluir automáticamente todas las columnas de la tabla o tablas especificadas. Las vistas dinámicas se pueden actualizar dinámicamente cuando se crean o modifican objetos relacionados u objetos ampliados. Las vistas estáticas pueden contener datos de varias tablas y las columnas necesarias de estas tablas se deben especificar en las clausulas SELECT y WHERE de la vista estática. Las vistas de base de datos se rellenan en función del objeto en el que se basan, si añade o elimina un atributo del objeto WORKODER, el atributo se añade o elimina la vista dinámica basada en el objeto. Las vistas también son una tabla virtual cuyo contenido está definido por una consulta. Al igual que una tabla, una vista consta de un conjunto de columnas y filas de datos con un nombre. Sin embargo, a menos que este indizada, una vista no existe como conjunto de valores de datos almacenados en una base de datos. Las filas y las columnas de datos proceden de tablas a las que se hace referencia en la consulta que define la vista y se producen de forma dinámica cuando se hace referencia a la vista.

Teoria: Python Orientado a Objetos

Python Orientado a Objetos

¿Qué es programación orientada a objetos? La programación orientada a objetos se basa en el concepto de crear un modelo del problema de destino en sus programas. La programación orientada a objetos disminuye los errores y promociona la reutilización del código. Python es un lenguaje orientado a objetos. Los objetos definidos en python tienen las características siguientes:

La programación orientada a objetos se define como un paradigma de la programación, una manera de programar específica, donde se organiza el código en unidades denominadas clases, de las cuales se crean objetos que se relacionan entre sí para conseguir los objetivos de las aplicaciones.

Características de Python OOP

Python incluye las características siguientes para dar soporte a la programación orientada a objetos:

Creación de objetos basada en clases

Las clases son plantillas para la creación de objetos. Los objetos son estructuras de datos con el comportamiento asociado.

Herencia con polimorfismo

Python da soporte a la herencia individual y múltiple. Todos los métodos de instancias de python son polimórficos y se pueden alterar temporalmente mediante subclases.

Encapsulación con ocultación de datos

Python permite ocultar los atributos. Cuando se ocultan los atributos, se puede acceder a los mismos desde fuera de la clase únicamente mediante los métodos de la clase. Las clases implementan métodos para modificar los datos.

Clases

Las clases son conjunto de objetos que constan de métodos y datos que resumen las características comunes de dicho conjunto. Las clases son como una plantilla que define las características y comportamiento de una entidad. Una clase es una entidad que define una serie de elementos que determinan un estado que es un dato y un comportamiento que son operaciones sobre los datos que modifican su estado.

Constructores

Los constructores son métodos especiales que se utilizan para inicializar un objeto recién creado y asignarle valores iniciales a sus variables de instancia. En los constructores se asignan los valores del nuevo objeto.

Atributos

Los atributos son una propiedad o característica que se puede asignar a un objeto denominado elemento. El uso del atributo puede asignar valores específicos a ciertos elementos. Los atributos se modelan o definen como elementos estructurales para ciertos tipos de objetos.

Métodos

Un método es una función que se define dentro de una clase y se utiliza para representar el comportamiento de un objeto. Los métodos se utilizan para realizar tareas específicas en un objeto, como cambiar el estado de un objeto, calcular un valor, interactuar con otros objetos, etc. En la programación orientada a objetos los métodos nos permiten realizar acciones en objetos de manera específica y eficiente.

Métodos mágicos

Los métodos mágicos son métodos especiales que tienen doble guion bajo al principio y al final de sus nombres.

Atributos privados

Atributo privado o encapsulación es la capacidad que tiene un objeto de ocultar su estado, de manera que sus datos solo se puedan modificar por medio de las operaciones (métodos) que ofrece.

Propiedades

Las propiedades se utilizan para encapsular atributos con métodos de obtención y establecimiento.

Herencia

La herencia es uno de los mecanismos más utilizados para alcanzar algunos de los objetivos más preciados en el desarrollo como lo son la reutilización y la extensibilidad.

Sobrecarga de métodos

La sobrecarga de métodos es la posibilidad de tener dos o más métodos con el mismo nombre, pero distintas funcionalidades. Es decir, dos o más métodos con el mismo nombre realizan acciones diferentes y el compilador usara una u otra dependiendo de los parámetros usados.

Herencia multinivel

La herencia multinivel es una clase derivada heredada de un clase base y, además, actuara como la clase base de otra clase.

Clases abstractas

Las clases abstractas son clases bases de una jerarquía y representan la funcionalidad común de un conjunto diverso de tipos de objetos.

Polimorfismo

El polimorfismo es la propiedad por la que es posible enviar mensajes sintácticamente iguales a objetos de tipos distintos. El único requisito que deben cumplir los objetos que se utilizan de manera poli formica es saber responder al mensaje que se les envía.

# Clases abstractas, no representan algo especifico y las podremos usar para crear otras clases. No pueden ser instanciadas, por lo que no se pueden crear nuevos objetos con ellas. Para crear una clase abstracta se debe importar la clase base abstracta y el decorador abstractmethod para el metodo abstracto.
from abc import ABC, abstractmethod

# Crear la clase abstracta, la cual desciende de ABC. Con esto no se podra crear instancias de la clase directamente, solo de aquellas que descienden de ella.
class Figura(ABC):
    # Crear un metodo abstracto para el area. No tiene codigo en su interior, ya que es un metodo vacio. Las clases hijas se ven obligadas a implementarlo. Hacemos uso del decorador abstractmethod
    @abstractmethod
    def area(self):
        pass

    @abstractmethod
    def perimetro(self):
        pass

# Crear una clase que dependa de la clase Figura
class Cuadrado(Figura):
    def __init__(self, lado):
        self.lado = lado

    # Implementar el primer metodo
    def area(self):
        return self.lado * self.lado
    
    # Implementar el segundo metodo
    def perimetro(self):
        return self.lado * 4
        
# Crear otra clase que descienda de la clase Figura
class Circulo(Figura):
    def __init__(self, radio):
        self.radio = radio

    def area(self):
        return 3.14159 * self.radio * self.radio
    
    def perimetro(self):
        return 2 * 3.14159 * self.radio

# No se puede instanciar una clase abstracta
# f1 = Figura()

# Instanciar el cuadrado
c1 = Cuadrado(5)

print("El area del cuadrado es", c1.area())
print("El perimetro del cuadrado es", c1.perimetro())

# Instanciar el circulo
c2 = Circulo(5)

# Sobrecarga de Metodos: Cuando heredamos metodos, en muchas ocasiones estos quedan absoletos por lo que deben ser actualizados, pero si lo hacemos en el elemento padre y lo borramos o actualizamos es posible que rompamos el programa si ese metodo estaba siendo utilizado por los elementos hijos. Para resolver esta situacion se crea un nuevo metodo dentro de la clase hijo con los requisitos actualizados. Por lo que la sobrecarga de metodos nos permite tomar el mismo nombre del metodo que esta en la clase padre, cambiando los argumentos que recibe y cambiar el proceso de los datos que devuelve.

        return "El nombre de la persona es " + self.nombre + " y tiene " + str (self.__edad) + " de edad."
    
    # Para acceder a un valor privado, creamos una funcion dentro del elemento padre

Django

¿Qué es Django? Django es un framework de desarrollo web de código abierto, escrito en python, que respeta el patrón de diseño conocido como modelo-vista-controlador. Django se utiliza para desarrollar aplicaciones web de forma rápida y eficiente. Además, facilita el trabajo de los desarrolladores al agrupar las diferentes funciones en una gran colección de módulos reutilizables, llamada marco de aplicación web. El marco de Django está bien organizado y proporciona una estructura para el desarrollo web como:

  • Autenticación de usuarios
  • Administración de contenido
  • Mapas del sitio
  • Fuentes RSS

Django utiliza modelos que actúan como interfaz entre la base de datos y el código del servidor. Son la única fuente definitiva de información sobre sus datos. Estos modelos de datos contienen los campos y las operaciones esenciales que necesita para interactuar con la base de datos. Los modelos de Django convierten así las tablas de base de datos en clases u objetos en el código python. Esto se denomina “mapeo objeto-relacional”.

El motor de plantillas: procesa el archivo de plantilla y crea la salida HTML final. Incluye los datos de la respuesta en esta salida.

La autenticacion de usuarios en Django se gestiona mediante
  • Cuentas de usuario
  • Permisos e indicadores de si o no que habilite a los usuarios realizar ciertas tareas del sitio web
  • Grupos de cuentas de usuario multiples con permisos similares.
  • Sesiones de usuario basadas en cookies.

En el almacenamiento en cache: que es lo que permite que el procesamiento de la aplicacion sea eficiente. Django ofrece un sistema de almacenamiento en cache robusto con diferentes niveles de almacenamiento en cache:

  • Permite almacenar en cache todo su sitio web.
  • Permite almacenar en cache la salida de funciones de vista especificas.
  • Permite almacenar en cache contenido especifico cuya creacion lleva mucho tiempo.
Las Computadoras Conectadas A La Web Se Llaman Clientes Y Servidores

Los clientes son dispositivos de los usuarios conectados a internet (por ejemplo, tu ordenador conectado a la red Wi-Fi o el telefono conectado a los datos moviles) y el software que se encuentra disponible y permite acceder a internet en dichos dispositivos (normalmente, un navegador web como firefox o chrome).

Los servidores son computadoras que almacenan paginas web, sitios o aplicaciones. Cuando un dispositivo cliente quiere acceder a una pagina web, una copia de la pagina web se descarga desde el servidor en el equipo cliente y se muestra en el navegador web del usuario.

HTTP: el protocolo de transferencia de hipertexto es un protocolo de aplicacion que define un idioma para que los clientes y servidores se pueden comunicar.

Patrón de diseño MVC

Modelo-Vista-Controlador es un patron de arquitectura de software, que separa los datos y principalmente lo que es la logica de negocio de una aplicacion de su representacion y el modulo encargado de gestionar los eventos y las construccion de tres componentes distintos que son el modelo, la vista y el controlador, es decir, por un lado define componentes para representacion de la informacion, y por otro lado para la interaccion del usuario. Este patron de arquitectura de software se basa en las ideas de reutilizacion de codigo y la separacion de conceptos, caracteristicas que buscan facilitar la tarea de desarrollo de aplicaciones y su posterior mantenimiento

El modelo define que datos debe contener la aplicacion. Si el estado de estos datos cambia, el modelo generalmente notificara a la vista (para que la pantalla pueda cambiar segun sea necesario) y, a veces, el controlador (si se necesita logica diferente para controlar la vista actualizada).

La Vista Define Como Se Deben Mostrar Los Datos De La Aplicacion

El controlador contiene una logica que actualiza el modelo y vista en respuesta a las entradas de los usuarios de la aplicacion.

En Django los templates son una forma conveniente de generar HTML dinamiacamente. Los templates contienen las partes estaticas de la salida HTML deseada, asi como alguna sintaxis especial que describe como se insertara el contenido dinamico.

    if request.method == "POST":
        personal = PersonalForm(request.POST)
        if personal.is_valid():
            personal.save()
            return redirect('inicio')
    else:
        personal = PersonalForm()
    return render(request, 'prueba/personal.html', {'personal':personal})

    if request.method == "POST":
        departamentos = DepartamentosForm(request.POST)

            departamentos.save()
            return redirect('inicio')

        departamentos = DepartamentosForm()
    return render(request, 'prueba/departamentos.html', {'departamentos':departamentos})

def signup(request):
    if request.method == 'GET':
        return render(request, 'signup.html', {"form": UserCreationForm})
    else:

        if request.POST["password1"] == request.POST["password2"]:
            try:
                user = User.objects.create_user(
                    request.POST["username"], password=request.POST["password1"])
                user.save()
                login(request, user)
                return redirect('tasks')
            except IntegrityError:
                return render(request, 'signup.html', {"form": UserCreationForm, "error": "Username already exists."})

        return render(request, 'signup.html', {"form": UserCreationForm, "error": "Passwords did not match."})

            new_task = form.save(commit=False)
            new_task.user = request.user
            new_task.save()
            return redirect('tasks')
        except ValueError:
            return render(request, 'create_task.html', {"form": TaskForm, "error": "Error creating task."})

Java
Concepto de Java

Java es un lenguaje de programación multiplataforma, orientado a objetos y ampliamente utilizado para codificar aplicaciones web. Java es rápido, seguro y confiable para codificar desde aplicaciones móviles y software empresarial hasta aplicaciones de macro datos y tecnologías del servidor.

Package: un package es una agrupación de clases. Es parecido a una caja que contiene las clases que queremos mantener en un solo lugar. También podría decirse que los package son equivalentes a librerías en otros lenguajes.

Import: cuando requerimos utilizar otras clases existentes en otros package esto se puede lograr con import.

Clases: en Java se puede crear diferentes tipos de clases; privadas, públicas y protegidas; y se utilizan de acuerdo a conveniencia de nuestro programa.

Constructores

Los constructores son la forma de crear los objetos en Java.

Métodos: en Java los métodos son lo que utilizamos para realizar alguna tarea en específico. Podemos decir que hay dos tipos de métodos en Java:

  • set sirve para manipular y/o fijar valores.
  • get sirve para obtener un valor de una variable.

Comentarios: estos pueden incluirse en cualquier parte del código. Son líneas que serán completamente ignoradas por el compilador y no afectará para nada el código del programa.

¿Qué es compilar?

Compilar es el proceso de transformar un programa informático escrito en un lenguaje conjunto de instrucciones en otro formato o lenguaje. Un compilador es un programa de computadora que realiza dicha tarea.

Las variables se utilizan durante la programación donde se guardan distintos tipo de valores. Estos datos se almacenan en la mayoría y se vinculan para poder operar con ellos cuando sea necesario.

  • String: es una clase que se utiliza para almacenar y manipular cadenas de caracteres.
  • Arrays: son estructuras de datos que se utilizan para almacenar un conjunto de elementos del mismo tipo.
  • Class: son estructuras de datos que se utilizan para representar un conjunto de atributos y métodos que definen una entidad.
  • Interface: son estructuras de datos que se utilizan para especificar un conjunto de métodos que deben ser implementados por una class.
  • Enum: son estructuras de datos que se utilizan para representar un conjunto finito de valores.
Operadores aritméticos
  • Suma (+)
  • Resta (-)
  • Multiplicación (*)
  • División (/)
  • Módulo o residuo (%)
  • Incremento (++)
  • Decremento (—)
Operadores lógicos
  • Y (&&)
  • O (||)
